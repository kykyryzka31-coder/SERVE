# Phase 2: контракт движка и проверка на устройстве

## Что реализовано

Java / Android API 26–35, без root и без сетевого разрешения. Пакет приложения
не изменён: `dev.serve.riseautomation`, версия 0.2.0 (code 2). Установка поверх
0.1.0 с тем же debug-ключом не очищает данные. Если подпись отличается,
не удаляйте приложение ради обновления: соберите APK с прежним ключом.

`AutomationService` владеет движком. Сессия запускается явной командой,
работает как foreground-служба `specialUse` с уведомлением и кнопками
паузы/возобновления/остановки/закрытия. На Android 13+ разрешение уведомлений
запрашивается только кнопкой в настройках приложения. Отказ не выдаёт доступ
и не мешает остановке из приложения; Android может скрыть уведомление в шторке.
На Android 14+ указан тип службы и описание специального назначения.
Проверка поведения foreground-службы на разных версиях Android ещё требуется.

Stop отменяет работу. Если включена плавающая панель, служба остаётся для
кнопки Start/Stop и уведомления «Остановлено», но не выполняет задачи.
«Закрыть» в уведомлении снимает панель и останавливает службу. Смахивание
приложения из списка недавних также останавливает сессию. Перезапуск процесса,
перезагрузка и повторное подключение Accessibility не возобновляют сессию
автоматически; `START_NOT_STICKY`, boot receiver отсутствует.

Настройки функций сохраняются в SharedPreferences. Данные пользователя не
сбрасываются. Состояние сессии и статистика хранятся в памяти: новая сессия
начинает новый отсчёт, пауза не входит во время работы. Успешные действия
учитываются только по подтверждённому результату исполнителя; нулевой результат,
отмена и заглушки не увеличивают статистику. Ошибка/тайм-аут — одна неудачная
попытка, пользовательская остановка не считается ошибкой.

## Планировщик и отмена

- `FairScheduler`: round robin между Городом, Миром и Альянсом; внутри
  категории — weighted round robin с весом приоритета 1–3. Низкий приоритет
  сохраняет очередь. Отключённые и непроверенные задачи не выбираются.
- `AutomationEngine`: монитор раз в 100 мс, отдельный единственный worker.
  Android main thread не выполняет задачи и не ждёт Future/завершения worker.
- На попытку: собственный cancellation token и deadline, настраиваемый в UI
  (15/30/60 секунд). При ошибке backoff 1/2/4/8/16/32/60 секунд с пределом
  60 секунд; подтверждённый успешный возврат сбрасывает backoff. После
  успешной попытки — минимум 500 мс до следующей попытки той же задачи.
- Пауза, Stop, отключение функции и потеря Accessibility отменяют token и
  прерывают worker. Поздний результат отменённой попытки игнорируется.
- Следующая задача не запускается, пока предыдущая реально не вышла, даже
  если она игнорирует interrupt. Безопасно убить произвольный Java-код нельзя:
  некорректный некооперативный исполнитель может задержать всю очередь.
  Все будущие исполнители обязаны проверять token между шагами, ограничивать
  ожидания и не выполнять действия в `finally`.
- Ошибки отдельного исполнителя изолированы от других категорий. Ошибка
  самого планировщика ставит сессию на паузу вместо бесконечного сбойного цикла.

## Accessibility и жесты

Служба включается только пользователем в системных специальных возможностях.
Приложение не использует ADB, root или запись Settings.Secure для её включения.
При отключении/прерывании доступ теряется, текущая попытка отменяется и сессия
ставится на паузу. После повторного включения требуется «Продолжить».

Разрешён только глобальный пакет RoK `com.lilithgame.roc.gp`; другие региональные
версии требуют отдельной проверки и явного изменения allowlist. Перед каждым
жестом заново проверяются активная сессия, cancellation token и пакет активного
окна. Системные настройки и другие приложения не являются целями.

`inspect()` возвращает ограниченный снимок доступных UI-узлов (до 200,
глубина до 15). Текст/снимки не записываются и не отправляются. `tapText()`
повторно ищет точный уникальный текст в текущем окне; неоднозначный результат
отклоняется. `tap()`/`swipe()` используют относительные координаты 0..1
в текущих границах окна с учётом его смещения и размеров. Это не распознавание
игровых элементов: без валидированного поиска целей безопасные RoK-сценарии
не готовы. Игровой canvas может вообще не предоставлять семантические узлы;
OCR/распознавание изображений в этой фазе не реализованы.

Жесты сериализованы. Уже переданный Android жест не имеет API для отзыва:
короткий tap (60 мс) или swipe (300 мс) может физически завершиться после Stop.
Новые жесты по отменённому token отклоняются, а старый callback не увеличивает
статистику. `dispatchGesture`/его callback подтверждают только доставку жеста,
а не успешное игровое действие. Будущий исполнитель обязан проверять
постусловие в игре перед возвратом положительного числа действий.

## Игровые функции

Шесть независимых записей в каталоге: ресурсы города, строительство, сбор на
карте, исследование тумана, помощь альянсу, пожертвования. Все имеют
`validated() == false`; даже выбранные переключателем функции не выполняются.
Их `execute()` намеренно выбрасывает исключение при ошибочном прямом вызове.
В production нет демонстрационных циклов с фиктивными успехами.

Исследование тумана — отдельная задача категории «Мир», без зависимости от
строительства или сбора. Запланирован путь через обычную ручную отправку
разведчика: проверить свободного разведчика, открыть интерфейс отправки,
выбрать область, отправить, подтвердить результат. Встроенное автоисследование
с лимитом 1,5 часа в день не используется. Этот сценарий не реализован и
не проверен. Перед включением любой функции нужны проверенные цели/состояния,
тайм-ауты шагов, идемпотентность, постусловия и тест на реальной игре.

## Проверки на устройстве — пока не выполнены для Phase 2

Старый skeleton пользователь уже запускал на LDPlayer Android 9. Это не
подтверждает работу новой версии. В облаке нет подключённого устройства
и `/dev/kvm`; приведённый ниже список — инструкция, не отчёт об успехе.

1. На локальном эмуляторе/устройстве установить debug APK поверх существующего
   с сохранением данных. Выполнить `scripts/adb-smoke.sh` с явным serial:
   проверяются запуск и экран статистики. Не подключать ADB к Интернету.
2. Без Accessibility: Start должен показать объяснение; отмена не запускает
   сессию. Включить службу вручную в Settings и вернуться в приложение.
3. Start: состояние «Сессия запущена», уведомление активно, успешных действий 0.
   Подождать: все заглушки оставляют счётчики нулевыми. Проверить Stop из
   приложения и уведомления, затем новый Start.
4. Pause: время работы перестаёт увеличиваться. Resume: время продолжается.
   Отключить Accessibility во время сессии: не позднее следующего обновления
   UI появляется пауза. Повторное включение само по себе не возобновляет работу.
5. Android 13–15: проверить выдачу и отказ POST_NOTIFICATIONS; отказ не мешает
   остановке из приложения. Android 14–15: проверить запуск foreground-службы.
6. Без overlay permission панель отсутствует. Отказ в системном разрешении не
   меняет состояние сессии. После выдачи повторно включить переключатель:
   одна кнопка 56dp, перетаскивание не нажимает Start/Stop. Проверить края,
   поворот, старт/стоп, отзыв разрешения и «Закрыть» в уведомлении.
7. Изменить выбор задач, приоритеты и время попытки, перезапустить приложение:
   значения сохранены, но игровые действия не выполняются.
8. Проверить телефон и планшет, портрет/альбом, крупный шрифт, вырезы и
   системную навигацию. Контент прокручивается и ограничен шириной 840dp;
   настройки доступны без наложения на игру.
9. Проверить остановку при удалении из недавних, системном завершении службы
   и перезапуске процесса. Автовозобновления быть не должно.

Тесты реальных жестов выполняются отдельно только на согласованном тестовом
экране игры. В приложении нет кнопки «попробовать тап» и скрытого игрового
тестового сценария. Unit-тесты используют изолированные Java task doubles,
не управляют игрой и не подтверждают RoK-автоматизацию.
